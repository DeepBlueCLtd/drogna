What changed from the first pass

The first wireframe drew all twenty declared components on a five-column grid. It was complete and it was a scribble: forty-one wires, and a loop you had to be told was a loop. Completeness is the Operator tab's job, and it already does it better.

This one draws thirteen. The write path is a straight column down the right — sample, validate, store. The four boxes at the left are laid out as an actual rectangle, because the forecast loop is a loop and a picture of it that is not a ring has thrown away the one thing worth saying. Fifteen wires. The seven components left out are listed under the drawing with the reason for each, and a gate fails on any component that is in neither list.

Drawn light and flat on purpose, so it is not mistaken for a picture of the finished dark panel. The content is real: labels from app/config/run.json, wires derived from contracts/topology.json, and the paragraphs are the draft copy.

    What is derived, and what is authored

    Derived — cannot go stale

    • Each node's text: that component's own declared label.
    • Every wire: the topology's publish/subscribe overlaps and the declared ports, collapsed to one line per pair. Solid crosses the broker; dashed is a port and carries no traffic.
    • The plane strip: the components that declare band: "plane", and the clock and heartbeat filters the flow chart already suppresses.
    • The three eras inside the coverage store: the enum in the holding master.
    • The interfaces on the arrow leaving the harness: the shell's declared endpoints.

    Authored — reviewed here

    • The ten steps, their order and their words.
    • Which cell each box sits in.
    • Which seven components are left out, and why.
    • Which live view each step links to.

    Held by a gate

    • A component that is neither drawn nor recorded as deliberately left out.
    • A box for something the configuration declares nothing for.
    • An omission with no reason given, or one that is also drawn.
    • Two boxes in one cell; a plane component drawn outside the strip.

    Nothing in the drawing is lit. It is the wiring, not the run: no heartbeat reaches it and no box claims to be alive, because the cheapest way to break the rule that illumination comes from heartbeats is a diagram that looks like a readout. The foot says so and links to Operator, where the live answer is.

    Still to settle

    1. Is this the right thirteen? The planner and telemetry are the two closest calls: they genuinely track the measurements, but they read the stores through ports rather than EDR, and each is a second argument the Map and Operator tabs already make.
    2. “Stored in Postgres.” Step 4 says it the only way that is true here: the store is in memory behind a store interface, in V1 it was PostgreSQL with PostGIS behind that same interface, and V3 brings the engines back. If you would rather the box itself said PostgreSQL / PostGIS, it would be naming an engine this build does not run.
    3. The arrow out. One box in the drawing is not a component — dashed, labelled anything outside, carrying the three served interfaces. It is the honest form of “downstream systems interrogate the store with EDR”: this page is just another client, and the Map's field arrives by the same request anyone outside would make.
    4. Prose length. Longer on the four steps carrying the argument — measurement in, the scheduler's two doors, the loop closing, and what the query layer serves — short elsewhere.
